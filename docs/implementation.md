# Implementation

How an agent turns the theme and the component specs into code. These conventions are technology independent: the target project may use plain HTML and CSS, React, Vue, Svelte, or another stack. The stack is a user decision; this file never imposes one.

Precedence: the component specs and `docs/conventions.md` take precedence over this file if they differ.

## Inputs

| Input | Source | Role |
|---|---|---|
| `DESIGN.md` | Theme, written in step 2 of the README | Token values, `## Icons`, `## Elevation & Depth` |
| `tokens.css` | Generated by `theme/theme.py` next to DESIGN.md (see `theme/questionnaire.md`) | The only place component code reads values from |
| `components/*.md` | Component specs | Anatomy, properties, states, token mapping, accessibility, behavior |

Never edit `tokens.css` by hand: change the theme and generate it again.

## Tokens

### Variable names

`tokens.css` holds one CSS custom property per token, with resolved values. The names are a fixed contract: component code uses only names of this contract (local aliases excepted, see Consumption rules).

| Spec reference | Variable |
|---|---|
| `{colors.<token>}` | `--color-<token>` |
| `{spacing.<token>}` | `--spacing-<token>` |
| `{rounded.<token>}` | `--rounded-<token>` |
| `{typography.<token>}` | five variables, see below |
| elevation level `level-<n>` | `--elevation-level-<n>`, `n` from 0 to 5 |

Note: the group is plural in DESIGN.md (`colors`) and singular in the variable (`--color-`).

| Typography property | Variable |
|---|---|
| Font family | `--typography-<token>-font-family` |
| Font size | `--typography-<token>-font-size` |
| Font weight | `--typography-<token>-font-weight` |
| Line height | `--typography-<token>-line-height` |
| Letter spacing | `--typography-<token>-letter-spacing` |

Examples: `{colors.primary-hover}` is `--color-primary-hover`; `{spacing.control-md}` is `--spacing-control-md`; `{typography.label-sm}` font size is `--typography-label-sm-font-size`.

The font family variable holds a fallback stack: the font entered by the user first, then generic families.

### Consumption rules

- Component code reads every visual value through these variables: color, dimension, radius, typography, shadow.
- Never a raw THEME value in component code: no hex, no theme pixel length, no shadow value, no font name of the text typography.
- Allowed as literals, because they are not theme values:
  - accessibility constants (24 by 24, 44 by 44 target sizes);
  - behavior constants fixed by the specs (for example 700 ms, 300 ms, 1000 ms, 2000 ms, the 6000 ms and 5000 ms of the toast, the 50% opacity of the dialog scrim);
  - the name of the icon font, which is data of the `## Icons` section of DESIGN.md.
- Name these literals as local aliases with a comment that cites their source (for example `--target-size-min: 24px; /* WCAG 2.5.8 */`). The aliases hold no theme value.
- Never a new variable that copies a token value. A local alias that points to a generated variable is allowed (for example a component-level variable set to `--color-primary`), as long as no value is duplicated.
- Primitive scale steps (for example `--color-blue-600`) exist in `tokens.css` but component code uses semantic tokens only, as the Token mapping of each spec does.
- Framework: use the same CSS variables. If the technology cannot read CSS variables (for example a native or canvas renderer), generate a token object from `tokens.css` with a 1:1 mapping (one entry per variable, same name, same value) and document the mapping in the project. Never retype values by hand.

## Dark mode

Applies only when the theme has the dark option (see "Dark mode" in `docs/conventions.md`, which takes precedence).

- `tokens.css` then holds two blocks: `:root` with `color-scheme: light`, then `[data-theme="dark"]` with `color-scheme: dark`, where every elevation variable is `none`. Same variable names in both blocks; only the values differ.
- The kit does not switch modes. The application sets `data-theme="dark"` (system preference, user setting, or anything else), on the root element or on an ancestor to scope it. Without the attribute, the light values apply.
- Component code is the same in both modes: it reads the same variables and never tests the mode.
- A component whose fill is `{colors.surface}` at `level-n` reads `--color-surface-level-n` instead (`level-0` keeps `--color-surface`). When the theme has the dark option, `tokens.css` defines `--color-surface-level-1` to `--color-surface-level-5` in `:root` too, equal to `--color-surface`, so the code needs no condition. Without the dark option these variables do not exist: a theme without it uses `--color-surface` only.
- No shadow in dark mode: depth comes from the surface step and the border, so keep the border of floating surfaces and overlay panels.

## Component API

- Property names and values are those of each spec's Properties table, unchanged. No synonym, no extra value.
- Defaults are those of the spec.
- Syntax is free: an attribute, a prop, a class modifier. A framework that requires another case (for example camelCase props) applies it mechanically to the same name (`icon-only` becomes `iconOnly`) and documents it.

Each configuration has the status given by the Status column of its spec (see Configuration status in `docs/conventions.md`). The agent handles it so:

| Status | What the agent does |
|---|---|
| `allowed` | Generates it as specified |
| `forbidden` | Refuses or reports it, never renders it silently (for example a selectable chip with an avatar) |
| `avoid` | Generates the recommended form by default (for example the floating button with a leading icon). Generates the discouraged case only if the project asks for it, and tells the user the reason given in the spec |
| `out-of-scope` | Invents nothing (for example a submenu). Tells the user the case is not specified and waits for a decision |

## State model

### Interactive states

`hover`, `pressed`, and `focus` come from the native mechanisms of the platform, never from script that imitates them.

| State | Mechanism | Rule |
|---|---|---|
| `hover` | Native pointer hover | Not applied when `disabled` or `loading` |
| `pressed` | Native active state (pointer down or key held) | Not applied when `disabled` or `loading` |
| `focus` | Native focus visible (keyboard focus), not every focus | Adds the focus ring only; combines with `hover` and `pressed` |

### State properties

A state property that accessibility can expose is exposed there, and the style reads the same attribute. One source of truth: no parallel class or flag that repeats the attribute.

| Property | Exposed by | Notes |
|---|---|---|
| `disabled` | Native disabled where the element supports it | Removed from the tab order by the platform |
| `selected` (chip) | `aria-pressed` | Toggle button semantics |
| `loading` (button) | `aria-busy` | Not native disabled: the button stays focusable; activation is ignored by script |
| `visited` (link) | Native `:visited`, color only | Not exposed to assistive technologies; the platform may not provide it |
| `value` (progress) | `aria-valuenow`, absent when indeterminate | `role="progressbar"`, see `components/progress.md` |
| `error` (text field) | `aria-invalid="true"` and `aria-describedby` to the error message | Present exactly when `error-message` is present; helper text is referenced the same way otherwise |
| `required`, `read-only` (text field) | Native `required`, native `readonly` | Native attributes, never a parallel class |
| `checked` (checkbox, switch) | Native `checked` | Switch: `role="switch"` on the checkbox input, see `components/switch.md` |
| `indeterminate` (checkbox) | Native `indeterminate` property | Announced as "mixed"; never set by the user's click |
| `value` (radio group) | Native `checked` on the selected radio, one shared `name` | Group in a `fieldset` with `role="radiogroup"` |
| `value`, `min`, `max`, `step` (slider) | Native `input` of type `range` | `aria-valuetext` only when `value-text` is set |
| `range` variant (slider) | Two native `input` elements of type `range` over one track, in a `group` named by `label` (or two ARIA `role="slider"` elements, with the full keyboard handled by the project) | One native range input handles one thumb only. Clamp each input to the other's value plus or minus `min-gap` and set `aria-valuemin` and `aria-valuemax` to those limits |
| `error` (checkbox, radio group, slider) | `aria-invalid="true"` and `aria-describedby` to the message | Group description on the `fieldset`; present exactly when `error-message` is |
| `value` (segmented control) | Native `checked` on the selected radio, one shared `name` | Group with `role="radiogroup"`, see `components/segmented-control.md` |
| `selected` (tab), `value` (tabs) | `aria-selected` on a button with `role="tab"`; `aria-controls` and `aria-labelledby` link tab and panel | Roving `tabindex`: the selected tab is the only tab stop; see `components/tabs.md` |
| `expanded` (accordion item) | `aria-expanded` and `aria-controls` on the header button | Hidden panel when collapsed; see `components/accordion.md` |
| `open` (tooltip) | Rendered or not rendered | `role="tooltip"`; trigger references it with `aria-describedby` while open, as in the spec |
| `open` (menu, select list, popover) | Rendered or not rendered | Trigger with `aria-expanded` and `aria-controls`, and `aria-haspopup` (`menu`, `listbox`, or `dialog`), as in each spec |
| `checked` (menu item) | `aria-checked` on `menuitemcheckbox` or `menuitemradio` | Roles `menu`, `menuitem`; `aria-disabled` for a disabled item, never native `disabled` |
| `value` (select) | Native `select` when it suffices; otherwise `role="combobox"` on the field with `aria-activedescendant`, and `aria-selected` on the chosen `option` | See `components/select.md` |
| `open` (dialog) | Native `dialog` element opened with its modal method (top layer, inert page, focus trap, `Escape`); `role="alertdialog"` for `confirmation` | Named by `aria-labelledby` to the title; `aria-describedby` to the body for `confirmation`; trigger with `aria-haspopup="dialog"`; see `components/dialog.md` |
| `open` (toast) | Rendered or not rendered, inside one live region that exists from the start | `aria-live="polite"` on the region; `role="alert"` on a `danger` toast; see `components/toast.md` |
| `interactive` (card) | One native `a` with `href`, or one native `button`, holding the whole card | `aria-labelledby` the heading, `aria-describedby` the body; `disabled` is native on the button, and a link card has no `href` when disabled; see `components/card.md` |
| `severity` (alert) | `role="status"` (`info`, `success`, `warning`) or `role="alert"` (`danger`) when inserted after load; no live role when rendered with the page | The icon has an image role and a name for its severity; see `components/alert.md` |
| `variant`, `size`, other options | Free (attribute, prop, modifier) | No accessibility attribute exists for them |

### Forced states for demonstration

Optional. A demo page may force a state (for example to show `hover` statically) with one dedicated attribute, such as `data-demo-state`, documented in the demo. It never ships in product code and never replaces the real mechanisms above.

## Box

- The dimensions of a spec are outer dimensions: the border is included. A height of `{spacing.control-md}` is the full height, border included. This is the `box-sizing: border-box` model: height and width include the border.
- The padding of a spec is measured inside the border: the border sits outside the padding and is part of the total height and width.
- Every variant reserves the border width `{spacing.border-width}`, transparent when the variant has no border. All variants of one size therefore share the same outer geometry, and a state change never moves the content.
- The focus ring is drawn outside the box at `{spacing.focus-ring-offset}` and never changes the layout. Exceptions: the chip `remove-button` and the search `clear-button` (see `components/chip.md`, `components/search-field.md`), and the segments of the segmented control, the tabs, the items of the menu, and the options of the select list, whose ring is drawn inside because their container clips or scrolls (see `components/segmented-control.md`, `components/tabs.md`, `components/menu.md`, `components/select.md`).

## Target size

- Requirement: hit area at least 24 by 24 CSS pixels (WCAG 2.2 criterion 2.5.8) for every interactive element, the chip `remove-button` and the search `clear-button` included; 44 by 44 for a floating button.
- Principle: when the rendered size is smaller, the hit area is extended invisibly, without changing the visual size and without overlapping the hit area of a neighbor.
- Technique: free (padding, pseudo-element, transparent overlay, platform hit slop).
- If the layout leaves no room to extend without overlap, report it to the user instead of shrinking the requirement.

## Icons

- Library and style: exactly those named in the `## Icons` section of DESIGN.md (for example Material Symbols, outlined). Never another style of the same library (filled instead of outlined), never another library.
- Glyphs: those named by the spec (`check-icon`: the library checkmark; `remove-button` and search `clear-button`: the library close icon; text field `error-icon`: the library error icon; `search-icon`: the library search icon; checkbox `check-icon`: the library checkmark; menu `check-icon` and select `check-icon`: the library checkmark; select `chevron`: the library chevron-down glyph, optionally turned up while open; popover, dialog and toast `close-button` and alert `close-button`: the library close icon; alert `icon`: the library information, check-in-circle, warning, and error glyphs by severity; toast `icon`: the library check-in-circle and error glyphs; checkbox `indeterminate-icon`: the library minus glyph; checkbox, radio group, and slider `error-icon`: the library error icon; segmented control `check-icon`: the library checkmark; accordion `chevron`: the library chevron-down glyph, turned up when expanded; avatar `fallback-icon`: the library person glyph; link `trailing-icon` for an external link: the library "open in new" glyph). The menu `dot` and the radio `dot` are plain circles, not library glyphs.
- Size: the `--spacing-icon-*` variable given by the size table of the spec.
- Defaults when `## Icons` does not state them: weight 400, no fill (fill 0), and optical size aligned with the icon size if the library supports an optical size axis. `## Icons` wins when it states a value.
- License: if the library carries a license (for example Material Symbols, Apache-2.0), respect its terms.
- Color: the current content color of the part (inherited, for example `currentColor`), never a fixed color.
- Delivery: free (icon font, inline SVG, package, sprite), as long as the glyphs come from the named library and style. The icon font name is an allowed literal (see Consumption rules), and loading the icon font is the project's responsibility (see Fonts).
- Library not available (no network, no package, no license): tell the user, name the missing glyphs, and wait for a decision. Never substitute another library or style silently, and never draw an approximation presented as the library icon.
- The button `spinner` is not a library icon: it is defined in `components/button.md`. The circular `progress` is not one either: it is defined in `components/progress.md`.

## Fonts

- Loading the fonts (text and icons) is the responsibility of the project. The kit loads nothing: `tokens.css` only names the font families.
- The agent tells the user which fonts to load: the family of each typography token in use, and the icon font of `## Icons`, with the weights and styles the specs use. It does not add a font file, a CDN link, or a package on its own.
- Until the fonts are loaded, the fallback stack of the font family variable applies.

## Floating surfaces and overlay panels

- Menu, select list, and popover follow "Floating surface" in `docs/conventions.md`. Where the platform has a native mechanism, use it rather than script: the HTML `popover` attribute (top layer, `Escape`, press outside), and CSS anchor positioning for the placement, with script only to flip and shift when it is not available.
- Focus management stays in script: where focus goes on open, and its return to the trigger on `Escape` (see each spec's Accessibility section).
- Dialog and toast follow "Overlay panel" in `docs/conventions.md`. For the dialog, use the native `dialog` element with its modal method: it provides the top layer, the inert page, the focus trap, `Escape`, and the `::backdrop` that carries the scrim (the `scrim` color at the constant opacity of the spec). Script only sets the initial focus, returns focus to the trigger, and applies the `loading` and `confirmation` rules of the spec. Lock the scroll of the page while it is open.
- The toast region is a plain element in the page, present from the start, in the top layer or above the page by layout; the toasts are inserted into it. Give it `role="region"` and the name "Notifications". The timer, its pause and its cancellation on focus, the stack, the wait while a dialog is open, and the `F6` / `Shift+F6` keys that move focus into and out of the region are script (document `F6` in the product's keyboard help).
- A native `select` is preferred to the custom select (see `components/select.md`); its closed field takes the text field tokens, its open list stays the platform's.

## Target browsers

Recent evergreen browsers. Modern selectors such as `:has()` are allowed. If the project targets older browsers, the agent adapts the code and tells the user.

## Scripted behavior

Some behaviors of the specs need script. They are requirements, not options.

Every Behavior requirement of a spec that is not implemented must be listed in the agent's report, by spec and by behavior (keyboard and dismissal requirements of its Accessibility section included, for example `Delete` and `Backspace` on the chip `remove-button`, or `Escape` on the tooltip, the menu, the select list, the popover, and the dialog; the focus trap and the initial focus of the dialog; the timer, the pause and the live region of the toast). This applies in particular when the requested output is static (for example HTML and CSS without script). Never omit one silently.

Static output also drops the attributes that depend on the open state. For example, without script the tooltip is never open, so the trigger has no `aria-describedby`. Such attributes are omitted and listed as not implemented, with the behaviors above.

## Files and class names

Recommendations only; the project conventions win.

- One file per component, plus `tokens.css` kept as generated.
- Plain CSS: BEM class names derived from the spec names: block = component, element = part, modifier = variant or size (for example `chip`, `chip__remove-button`, `button--tonal`, `button--size-m`).
- Framework: one component per spec, named after it (24 components: Button, Chip, Tooltip, Divider, Link, Badge, Avatar, Progress, TextField, SearchField, Checkbox, Radio, Switch, Slider, SegmentedControl, Tabs, Accordion, Menu, Select, Popover, Dialog, Alert, Toast, Card); the checkbox and radio groups are CheckboxGroup and RadioGroup.
- Demo pages stay apart from component files.
