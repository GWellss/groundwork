# Contributing to Groundwork

Thank you for your interest. Groundwork is a reference kit of component specifications, a theme questionnaire, and a theme script. Contributions are welcome, in English.

By contributing, you agree that your contribution is released under the MIT license of this repository. Please follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Before you start

- Open an issue on GitHub to discuss anything larger than a typo or a small fix.
- Read `docs/conventions.md`: it holds every shared rule (token references, contrast pairs, states, dark mode, elevation, naming, spec format).
- Send one pull request per change.

## Proposing or changing a component spec

A spec lives in `components/<component>.md`. The reference spec is `components/button.md`.

1. Follow the 14 sections of "Component spec format" in `docs/conventions.md`, in that order. A section that does not apply stays, with one line saying why.
2. Reference tokens by path, for example `{colors.primary}`. Never copy a token value into a spec.
3. Use kebab-case for file names, token names, variants, states, and parts.
4. Give every configuration of the Anatomy table one status: `allowed`, `forbidden`, `avoid`, or `out-of-scope`.
5. Declare every text and background pair so that the 4.5:1 contrast rule can be checked.
6. Keep the justification of your decisions out of the spec. Put it in `docs/rationale/<component>.md`, a table with the columns `Decision` and `Reason`, written for human contributors. See `docs/rationale/toast.md` for an example.
7. If your change needs a new token, update the theme rules (`theme/questionnaire.md`) and the theme script (`theme/theme.py`) in the same pull request.

## Regenerating the examples

The example themes in `examples/` are generated by the theme script. Run, from the repository root:

```
python3 theme/theme.py --out examples/default/DESIGN.md
python3 theme/theme.py --dark --dark-brand accept --out examples/default-dark/DESIGN.md
```

The first command writes `DESIGN.md` and the `tokens.css` next to it. The second also writes `DESIGN.dark.md`, and its `tokens.css` holds a light block and a `[data-theme="dark"]` block. Run `python3 theme/theme.py --help` to list the options. Commit the regenerated files with the change that caused them. The CI checks that the examples are up to date.

## Checks to run

```
python3 theme/theme.py --selftest
```

It must end with `selftest ok`. If you changed a theme file, also run the DESIGN.md lint with the pinned version: `npx @google/design.md@0.4.0 lint <file>`. The expected result is 0 errors and 0 `contrast-ratio` warnings.
